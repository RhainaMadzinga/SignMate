SignMate Avatar Pipeline Diagram

This document shows the planned and tested avatar pipeline for SignMate. The avatar work aimed to connect BSL sign data, processed landmarks, JSON files and Unity/manual animation into a visual signing output.

```
Raw Sign Data Original or collected BSL sign videos organised by gloss label.
↓
MediaPipe / Backend Processing Extracts pose, hand and face landmarks from sign videos.
↓
Processed Landmark Files CSV, JSON or NPY files containing structured landmark data.
Fixed-Length Sequences Frame sequences prepared for recognition and prediction work.
↓
JSON Sign / Movement Files Stores gloss labels, frame data, pose landmarks, hand landmarks and optional prediction output.
↓
Unity JSON Playback Loads sign data or manifest mappings for playback/testing.
Skeleton Video Output Visualises processed pose/skeleton movement as output videos.
Manual Animation Selected signs manually animated in Unity for clearer avatar playback.
↓
Avatar Output Unity/avatar scene used to test sign playback, pose movement, handshape and animation sequences.
```

Connection to the iOS App

  • The app produces a gloss sequence through TranslationService.
  • AvatarService prepares animation file names from the translation result.
  • The gloss names are intended to match JSON files, Unity manifest entries or animation names.
  • Example: thank you → thank_you → thank_you.json → thank_you avatar animation.

Important Limitation

The final live connection between the iOS app and the completed Unity avatar playback was not fully completed by the deadline. However, the project produced evidence of the intended pipeline through app mapping, JSON files, skeleton outputs, Unity avatar setup and manual animation work.

The avatar pipeline shows that the project was designed as a modular system. Even though full live integration was incomplete, the dataset, JSON, Unity and app mapping evidence demonstrate how the components were intended to connect.
