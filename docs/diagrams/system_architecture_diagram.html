SignMate System Architecture Diagram

This diagram shows the overall architecture of the SignMate prototype. The system was designed as a modular pipeline connecting the iOS app, translation logic, dataset/backend processing and Unity/avatar output.

User Enters English text into the SignMate app.
↓
iOS App Interface SwiftUI screens including login, text input, processing, result, saved translations and settings.
Firebase Authentication Supports login, account creation, password reset and sign-out state.
↓
TranslationService Processes English input using supported signs, phrase mapping and context-recognition rules.
TranslationResult Stores original text, gloss sequence, subtitle text, animation IDs and optional avatar URL.
AvatarService Prepares gloss sequence and animation files for future avatar playback.
↓
Dataset and Backend Processing Raw sign files, processed landmarks, fixed-length sequences, LSTM recognition and prediction output.
JSON Sign Files Structured sign data for prediction, movement export or avatar playback.
↓
Unity / Avatar Pipeline Unity avatar scene, manual animations, JSON playback, skeleton outputs and avatar testing.
The final system was developed as a modular prototype. The app, dataset, backend and avatar components were connected through shared gloss names and documented integration points, but the final live app-to-avatar connection was not fully completed by the deadline.
